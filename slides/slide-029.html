Graphical, low-code authoring with extensions.

Explain a business agent through the decisions its owner must make.
Instructions describe its purpose and limits.
Knowledge supplies information it can consult.
Tools let it perform configured operations, such as reading a record or sending a message.
Conversational behavior and explicit business logic can be combined.

Low-code describes an authoring approach, not an exclusive audience.
Developers can extend an agent and review definition changes using familiar editing tools.
Test in the actual user experience before publishing.

A harness is the runtime coordinating model calls and tools.
Knowledge, authentication, tools and channels depend on the selected experience.
Choose the runtime that supports the intended job.

Technical reference, not spoken:
The standard-harness VS Code extension is GA.
Applying changes updates the target environment, not publication.
The separate Studio MCP development route has no established GA label.
Standard Teams group chats/channels cannot use end-user-authenticated SharePoint knowledge, which requires 1:1 chat.
