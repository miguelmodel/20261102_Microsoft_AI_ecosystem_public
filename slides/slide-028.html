GitHub Copilot app: repository-optional Projects and canvases for feedback analysis, recurring summaries, planning, and artifacts.

Describe the output as reviewable software work.
Copilot can help a team understand an inherited application, propose a bounded fix, create tests, or improve documentation.
A maintenance task may add no AI feature to the finished application.

The app also documents Projects that can start without a repository, including customer-feedback analysis and recurring summaries.
Canvases support personal planning and document, spreadsheet, or slide collaboration.
This supports low-code-style delegation and developer-adjacent work, not a professional-developers-only restriction.
It does not establish M365 app embedding, source permissions, or runtime parity.

Assistive work keeps a person close to individual suggestions.
Agentic work delegates several steps toward a clear goal.
Give that task acceptance criteria: what should change, and how will the team check it?
Delegating execution does not delegate accountability.
A proposed change still needs human review and appropriate testing; generated code and AI review can both miss defects.

An editor, terminal, and cloud session can have different permissions and approval behavior.
Capabilities and safeguards vary by surface, plan and policy.
Do not assume every tool call receives a fresh confirmation.

Optional detail; skip if short on time:
App Projects are public preview, while a whole-app formal GA milestone was not established.
App access, plan/provider eligibility, organization policy, and local/cloud execution differ by route.
Autopilot and scheduled work do not require a fresh approval for every operation.
GitHub's documentation does not settle content-exclusion and terminal-policy coverage uniformly across surfaces.
Validate the exact execution environment before relying on a restriction for confidential work.
